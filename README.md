# Local RAG

Локальное приложение собирает документы в добавляемую коллекцию, извлекает текст, строит два индекса фрагментов и сравнивает baseline и RAG-ответы через выбранную облачную модель. Файлы, извлечение, embeddings, retrieval, индекс и SQLite остаются локально. Цитаты строятся отдельно из реально найденных фрагментов.

## Возможности и границы

- Локальный импорт PDF, UTF-8 TXT, Markdown, статического HTML и текстовых файлов исходного кода. Веб-адреса и внешняя загрузка файлов не поддерживаются.
- Ограничения: 256 MiB на файл и общий объём 512 MiB для ожидающих источников и добавляемых файлов одного запуска индексации. Следующую пачку добавляйте после индексации ожидающих файлов.
- Текстовые слои PDF извлекаются утилитами Poppler `pdfinfo` и `pdftotext`; OCR не выполняется. Номера страниц без извлечённого текста показываются в записи источника.
- HTML разбирается как статический текст; JavaScript не запускается, ресурсы по ссылкам не загружаются.
- Для TXT, Markdown и исходного кода сохраняются номера строк, для HTML — разделы заголовков. PDF сохраняет диапазоны страниц.
- Две стратегии: фиксированные окна по 500 слов с перекрытием 50 слов и фрагментация с границами разделов и тем же пределом окна.
- Benchmark загружается пользователем отдельно в JSON: ровно десять вопросов, ожидаемые факты и ссылки на `sourceId` с номером страницы, диапазоном строк или названием раздела. До принятия набора приложение проверяет, что источники существуют, готовы к поиску и поддерживают указанное место. Невалидный набор отклоняется без замены принятого fixture, результатов, оценок и заметок.
- Оценки PASS / PARTIAL / FAIL и заметки сохраняются локально. При удалении источника удаляются его копия, индексные фрагменты и связанные результаты benchmark; набор вопросов остаётся, но требует исправить ссылки.
- Повторный импорт тех же байтов по SHA-256 использует существующий `sourceId`; одинаковые имена с разным содержимым остаются отдельными источниками. После ошибки индексации повторная загрузка возвращает прежний источник в `PENDING`, а не создаёт дубль.

## Требования

- Java 17 или новее;
- `pdfinfo` и `pdftotext` из Poppler для PDF;
- Ollama на `127.0.0.1` с моделью `embeddinggemma:300m` только для embeddings;
- действующий API key в переменной окружения `DEEPSEEK_API_KEY`.

Генерация и reranking выполняются через DeepSeek Cloud; в интерфейсе доступны `deepseek-flash` и `deepseek-v4-pro`. Провайдер обрабатывает переданный текст согласно своим условиям хранения и использования; перед отправкой чувствительных документов проверьте эти условия. Не храните ключ в файлах проекта, SQLite, фикстурах или логах.

## Запуск

```bash
./gradlew test
./gradlew run
```


Откройте `http://127.0.0.1:8765/`. Выберите несколько локальных файлов и нажмите «Добавить выбранные». Импортированные документы сначала имеют состояние «ожидает индексации». Кнопка индексации показывает полный список и размер и требует отдельного подтверждения. Один запуск индексации обрабатывает до 512 MiB; следующий набор можно добавить после завершения текущего. Новые источники добавляются к коллекции и не требуют повторной обработки готовых документов.

В интерфейсе задайте вопрос и выберите стратегию. Baseline отправляет провайдеру только исходный вопрос и не использует документы. Raw retrieval показывает unfiltered cosine-поиск по исходному вопросу. Enhanced retrieval локально нормализует запрос (NFKC, регистр, пробелы и типографская пунктуация), отбирает фрагменты с cosine score не ниже `0.20` и отправляет в DeepSeek reranker только вопрос, тексты кандидатов и их локальные индексы. Источники, разделы, chunk IDs, locations, embeddings, полный документ и benchmark expected facts в reranker payload не входят. Reranker обязан вернуть точную перестановку кандидатов; при ошибке raw-список не подменяет enhanced-результат. Cosine score — мера сходства, не вероятность.

RAG использует только enhanced-фрагменты. Если их нет, baseline всё равно возвращается, а RAG отвечает ровно: «Не знаю на основе текущих источников. Уточните вопрос или добавьте источник.» Вызов генерации для RAG пропускается, citations пусты. Цитаты привязаны к найденному chunk и показывают источник, раздел, chunk ID, страницу или строки, cosine score и точную выдержку длиной не более 300 символов.

Benchmark сравнивает raw и enhanced retrieval для десяти вопросов при обеих стратегиях chunking. UI сохраняет упорядоченные списки и показывает ранг первого ожидаемого источника, reciprocal rank, Hit@4 и MRR отдельно по стратегии и типу retrieval. Один benchmark выполняет не более 50 облачных запросов: 10 baseline, до 20 reranker и до 20 RAG; пустые enhanced-списки пропускают reranker и RAG-вызов. Пара provider/model фиксируется на весь запуск, результаты сохраняют оба ID. Ожидаемые факты используются только локально.

`examples/synthetic-observatory.md` — вымышленная коллекция из 25 разделов для проверки индексации и локального retrieval. Сгенерировать её заново можно командой:

## Benchmark JSON

Корневой объект содержит массив `questions`. Каждая запись имеет уникальный `id`, текст `question`, непустой массив `expectedFacts` и непустой массив `expectedSources`. UUID в примере ниже синтетический; подставьте настоящий полный `sourceId` из локального API `curl -sS http://127.0.0.1:8765/api/sources`. UI показывает только первые 12 символов ID для сверки.
```json
{
  "questions": [
    {
      "id": "q01",
      "question": "Где описаны основные маркеры?",
      "expectedFacts": ["В документе перечислены маркеры маршрута."],
      "expectedSources": [
        {
          "sourceId": "00000000-0000-4000-8000-000000000000",
          "location": { "lineStart": 12, "lineEnd": 16 },
          "section": "Обзор"
        }
      ]
    }
  ]
}
```

Для PDF `location` указывает `pageStart` и `pageEnd`; для текстовых файлов допустимы `lineStart` и `lineEnd`; для HTML надёжной ссылкой является название существующего `section`. Неиспользуемый вид координат можно опустить. Ссылки на image-only страницы PDF не принимаются.

## Локальные данные и облачная генерация

По умолчанию база SQLite находится в `~/.local/share/local-rag/local-rag-v11.sqlite`, копии импортированных файлов — в соседнем каталоге `sources/`, а выбранная пара provider/model — в `model-selection.json`. Каталог источников создаётся с правами владельца (`0700`), копии, база и файл выбора — `0600` на POSIX-системах. Данные на диске не шифруются приложением; эти права не защищают их при компрометации учётной записи или диска. Для чувствительных документов используйте шифрование диска и сначала проверьте условия обработки DeepSeek.

Каталог провайдеров и моделей хранится в `config/providers.json`, значения по умолчанию — в `config/agent.json`. Изменение выбора в интерфейсе сохраняется локально; credentials не сохраняются. Установите `DEEPSEEK_API_KEY` через окружение или secret manager до запуска приложения. Переменная читается только при генерации и reranking через облачный API; интерфейс показывает только наличие ключа и имя переменной.

Переопределения задаются окружением:

- `LOCAL_RAG_DATA_DIR` — корневой каталог данных;
- `LOCAL_RAG_PORT` — порт интерфейса, по умолчанию `8765`;
- `LOCAL_RAG_OLLAMA_URL` — loopback Ollama для embeddings, по умолчанию `http://127.0.0.1:11434`.

Приложение привязывает HTTP-интерфейс к `127.0.0.1`; внешний хост не обслуживается. Адрес Ollama должен использовать HTTP и loopback-хост. Запросы генерации идут по HTTPS к DeepSeek; перенаправления не выполняются. HTML- и текстовые парсеры не обращаются в сеть.

## Проверки

```bash
./gradlew test
xvfb-run -a -s '-screen 0 1440x1000x24' ./gradlew browserTest
```

Детерминированные тесты используют временную SQLite, синтетические документы, тестовый PDF-процесс и fake HTTP-сервисы Ollama/DeepSeek на loopback. Проверяются изоляция baseline/RAG/reranker payload, безопасная перестановка индексов reranker, no-fallback при ошибке, пустой enhanced retrieval с сохранением baseline, точные citations и quotes, Hit@4/MRR, максимум 50 облачных вызовов benchmark и миграция старой SQLite без потери ответов, оценок и заметок. Обычные тесты не требуют секретов и не обращаются к внешним API.

`test` не включает browser journey. `browserTest` запускает настоящее приложение и Chromium под Xvfb; на Linux нужны `xvfb-run` и зависимости Chromium, которые Playwright сообщает при первом запуске. Browser acceptance проверяет смену и локальное сохранение модели, облачные ответы через fake provider, benchmark и поведение без credential.

### Результаты проверки

- `./gradlew test` — успешно.
- `xvfb-run -a -s '-screen 0 1440x1000x24' ./gradlew browserTest` — успешно в составе полного delivery acceptance. Playwright вывел предупреждение об отсутствующем `libavif16`; browser suite завершился успешно.
- Отдельные live smoke-проверки использовали только synthetic baseline/RAG-вопрос и synthetic reranker-кандидаты. `deepseek-flash` вернул HTTP 200 и перестановку `[1,0,2]`; реальные документы и данные LTE не отправлялись. API key не печатался.
