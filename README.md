# Local RAG

Local RAG — локальное приложение для импорта документов, индексации и ответов по ним. Файлы, embeddings, retrieval, reranking, индекс и SQLite остаются локально. Для генерации можно выбрать DeepSeek Cloud или локальную Ollama-модель; ссылки на источники приложение строит отдельно из реально найденных фрагментов.

## Возможности и границы

- Локальный импорт PDF, UTF-8 TXT, Markdown, статического HTML и текстовых файлов исходного кода. Веб-адреса и внешняя загрузка файлов не поддерживаются.
- Ограничения: 256 MiB на файл и общий объём 512 MiB для ожидающих источников и добавляемых файлов одного запуска индексации. Следующую пачку добавляйте после индексации ожидающих файлов.
- Текстовые слои PDF извлекаются утилитами Poppler `pdfinfo` и `pdftotext`; OCR не выполняется. Номера страниц без извлечённого текста показываются в записи источника.
- HTML разбирается как статический текст; JavaScript не запускается, ресурсы по ссылкам не загружаются.
- Для TXT, Markdown и исходного кода сохраняются номера строк, для HTML — разделы заголовков. PDF сохраняет диапазоны страниц.
- Две стратегии: фиксированные окна по 500 слов с перекрытием 50 слов и фрагментация с границами разделов и тем же пределом окна.
- Benchmark загружается пользователем отдельно в JSON: ровно десять вопросов, ожидаемые факты и ссылки на `sourceId` с номером страницы, диапазоном строк или названием раздела. До принятия набора приложение проверяет, что источники существуют, готовы к поиску и поддерживают указанное место. Невалидный набор отклоняется без замены принятого fixture, результатов, оценок и заметок.
- Оценки PASS / PARTIAL / FAIL и заметки сохраняются локально. При удалении источника удаляются его копия, индексные фрагменты и связанные результаты benchmark; набор вопросов остаётся, но требует исправить ссылки.
- Повторный импорт тех же байтов по SHA-256 использует существующий `sourceId`; одинаковые имена с разным содержимым остаются отдельными источниками. После ошибки индексации повторная загрузка возвращает прежний источник в `PENDING`, а не создаёт дубль.

## Требования

- Java 17 или новее;
- `pdfinfo` и `pdftotext` из Poppler для PDF;
- Ollama на `127.0.0.1` с `embeddinggemma:300m` для embeddings и `qwen2.5:3b` для локального reranking;
- для локальной генерации — загруженная в Ollama модель `qwen2.5:3b`, `qwen2.5:3b-instruct-q5_K_M` или `qwen2.5:7b`;
- `DEEPSEEK_API_KEY` нужен только при выборе DeepSeek Cloud для генерации.

Генерация использует выбранные provider/model: `deepseek-flash` и `deepseek-v4-pro` доступны через DeepSeek Cloud, `qwen2.5:3b`, `qwen2.5:3b-instruct-q5_K_M` и `qwen2.5:7b` — через локальную Ollama. Поиск и reranking выполняются локально при любом выборе. Ошибка выбранной модели не переключает приложение на другого провайдера. При Cloud-провайдере отправляемые ему данные обрабатываются по его условиям; перед отправкой чувствительных документов проверьте их. Не храните ключ в файлах проекта, SQLite, фикстурах или логах.

## Запуск

```bash
./gradlew test
./gradlew run
```


Откройте `http://127.0.0.1:8765/`. Выберите несколько локальных файлов и нажмите «Добавить выбранные». Импортированные документы сначала имеют состояние «ожидает индексации». Кнопка индексации показывает полный список и размер и требует отдельного подтверждения. Один запуск индексации обрабатывает до 512 MiB; следующий набор можно добавить после завершения текущего. Новые источники добавляются к коллекции и не требуют повторной обработки готовых документов.

В интерфейсе задайте вопрос, выберите provider/model и стратегию. Baseline отправляет выбранной модели только исходный вопрос и не использует документы. Raw retrieval показывает unfiltered cosine-поиск по исходному вопросу. Enhanced retrieval локально нормализует запрос (NFKC, регистр, пробелы и типографская пунктуация), отбирает фрагменты с cosine score не ниже `0.20` и локально rerank-ит их через `qwen2.5:3b`, передавая только вопрос, тексты кандидатов и их локальные индексы. Источники, разделы, chunk IDs, locations, embeddings, полный документ и benchmark expected facts в reranker payload не входят. Reranker обязан вернуть точную перестановку кандидатов; при ошибке raw-список не подменяет enhanced-результат. Cosine score — мера сходства, не вероятность.

RAG использует только enhanced-фрагменты. Если их нет, baseline всё равно возвращается, а RAG отвечает ровно: «Не знаю на основе текущих источников. Уточните вопрос или добавьте источник.» Вызов генерации для RAG пропускается, citations пусты. Цитаты привязаны к найденному chunk и показывают источник, раздел, chunk ID, страницу или строки, cosine score и точную выдержку длиной не более 300 символов.

Benchmark сравнивает raw и enhanced retrieval для десяти вопросов при обеих стратегиях chunking. UI сохраняет упорядоченные списки и показывает ранг первого ожидаемого источника, reciprocal rank, Hit@4 и MRR отдельно по стратегии и типу retrieval. Один запуск использует выбранную пару provider/model для всех генераций: до 10 baseline и до 20 RAG-ответов; при Cloud-провайдере это до 30 облачных запросов. Локальный reranker выполняет не более 20 вызовов; пустые enhanced-списки пропускают reranking и RAG-вызов. Результаты сохраняют оба ID, ожидаемые факты используются только локально. Benchmark не запускает сравнение разных моделей.

## Чат и память

- Вкладка «Чат» не заменяет коллекцию. Создайте сессию, задайте вопрос и продолжайте диалог; история и состояние задачи сохраняются в локальной SQLite. URL содержит ID сессии и открывает ту же историю после перезапуска. Название сессии модель создаёт после первого успешного ответа и затем оно не меняется; сессию можно удалить с подтверждением.
- В чате доступны отдельные выпадающие списки provider/model. Выбор сохраняется для каждой сессии отдельно; новая сессия наследует текущий выбор в разделе коллекции, а изменение выбора коллекции не меняет существующие сессии. Каждый ответ сохраняет фактические provider/model и время обработки полного хода до записи результата в SQLite. Исторические ответы без этих полей не получают выдуманную атрибуцию.
- Если сохранённый выбор коллекции повреждён или больше не входит в каталог, новая Chat-сессия не получает пару провайдера по умолчанию. Требование явно выбрать provider/model в этой сессии сохраняется и после исправления общего выбора коллекции; отправка остаётся заблокированной, пока выбор не сделан в самой сессии.
- Каждый ход выполняет enhanced retrieval и reranking локально по READY-источникам. В выбранную генеративную модель передаются текущий вопрос, до восьми последних сообщений только этой сессии, её task state, до трёх выбранных по локальному cosine-similarity фактов SESSION и до трёх SHARED, а также тексты найденных document candidates. Порог выбора памяти — `0.20`; чужая история и чужие SESSION facts не передаются. Общие факты доступны разным сессиям после автоматической классификации моделью. Ollama-провайдер использует только настроенный loopback endpoint; ошибка локальной модели не включает Cloud-провайдер.

Состояние задачи ограничено 20 уточнениями, 20 ограничениями и 20 терминами; цель, каждая запись и поля термина/определения ограничены 500 символами. Превышение лимита отклоняется без усечения. Сгенерированный факт термина сохраняет оба поля целиком.

- Task state (цель, уточнения, ограничения и термины) модель меняет только при ясном изменении беседы; состояние можно исправить в интерфейсе. Каждый structured response также может автоматически сохранить новые SESSION или SHARED facts без отдельного подтверждения каждого факта. Session-facts pane и promotion control отсутствуют; общие факты можно просматривать, менять и удалять. Ответ показывает только выбранные моделью document citations и memory references, проверенные по candidate IDs текущего хода; source, location и quote citation восстанавливаются из локальных данных. Ссылки не гарантируют семантическую опору ответа, а пустой список refs сам по себе не означает, что ответ должен быть отказом.

- System prompt требует точный отказ и пустые evidence refs, если documents и выбранная память не подтверждают фактический ответ, включая случай пустых candidate lists. Structured generation при этом выполняется: модель может также классифицировать новые пользовательские факты или обновить task state. Семантическую достаточность оценивает модель; backend не проверяет entailment независимо.

- SQLite и память хранятся локально без шифрования приложения. Retrieval, embeddings и reranking не отправляют документы во внешний API. При выборе Cloud-провайдера ему передаются сообщения, состояние задачи, выбранные факты SESSION/SHARED и найденные тексты согласно границам выше; условия хранения DeepSeek не проверены. При выборе Ollama генерация идёт через loopback без автоматического перехода к Cloud. Автоматическая память может включить чувствительные сведения; проверяйте выбранный provider/model перед отправкой каждого вопроса.

## Benchmark JSON

Корневой объект содержит массив `questions`. Каждая запись имеет уникальный `id`, текст `question`, непустой массив `expectedFacts` и непустой массив `expectedSources`. UUID в примере ниже синтетический; подставьте настоящий полный `sourceId` из локального API `curl -sS http://127.0.0.1:8765/api/sources`. UI показывает только первые 12 символов ID для сверки.
```json
{
  "questions": [
    {
      "id": "q01",
      "question": "Где описаны основные маркеры?",
      "expectedFacts": ["В документе перечислены маркеры маршрута."],
      "expectedSources": [
        {
          "sourceId": "00000000-0000-4000-8000-000000000000",
          "location": { "lineStart": 12, "lineEnd": 16 },
          "section": "Обзор"
        }
      ]
    }
  ]
}
```

Для PDF `location` указывает `pageStart` и `pageEnd`; для текстовых файлов допустимы `lineStart` и `lineEnd`; для HTML надёжной ссылкой является название существующего `section`. Неиспользуемый вид координат можно опустить. Ссылки на image-only страницы PDF не принимаются.

## Локальные данные и выбор генерации

По умолчанию база SQLite находится в `~/.local/share/local-rag/local-rag-v11.sqlite`, копии импортированных файлов — в соседнем каталоге `sources/`, а общий выбор provider/model — в `model-selection.json`. Каталог источников создаётся с правами владельца (`0700`), копии, база и файл выбора — `0600` на POSIX-системах. Выбор provider/model каждой сессии и provenance/время ответа хранятся в SQLite. Данные на диске не шифруются приложением; эти права не защищают их при компрометации учётной записи или диска. Для чувствительных документов используйте шифрование диска и учитывайте границы передачи для выбранного генеративного провайдера.

В loopback-режиме каталог включает Cloud-провайдеры и Ollama; для DeepSeek Cloud ключ `DEEPSEEK_API_KEY` передаётся через окружение или secret manager, credentials не сохраняются. В LAN-режиме каталог содержит только Ollama: выбор Cloud-провайдера из UI и API отклоняется, сохранённый Cloud default заменяется локальным default с предупреждением; LTE-вопросы и источники не отправляются в Cloud.

Переопределения задаются окружением:

- `LOCAL_RAG_DATA_DIR` — корневой каталог данных;
- `LOCAL_RAG_PORT` — порт интерфейса: по умолчанию `8765` для loopback; LAN-режим принимает только `8767`;
- `LOCAL_RAG_OLLAMA_URL` — адрес Ollama для embeddings, reranking и локальной генерации, по умолчанию `http://127.0.0.1:11434`;
- `LOCAL_RAG_BIND_ADDRESS` — конкретный адрес привязки; по умолчанию `127.0.0.1`. LAN-режим принимает только Wi-Fi-IP `192.168.2.160` и порт `8767`; wildcard и другие IP/порты отклоняются.

По умолчанию HTTP-интерфейс слушает только `127.0.0.1`; внешний хост не обслуживается. Адрес Ollama должен использовать HTTP и loopback-хост. Cloud-генерация разрешена только в loopback-режиме и идёт по HTTPS к DeepSeek; перенаправления не выполняются. HTML- и текстовые парсеры не обращаются в сеть.

## Доступ из локальной сети и параллельные сессии

По умолчанию HTTP слушает только `127.0.0.1`. Для доступа из домашней Wi-Fi-сети используйте только закреплённый адрес `192.168.2.160` и порт `8767`:

```bash
export LOCAL_RAG_BIND_ADDRESS=192.168.2.160
export LOCAL_RAG_PORT=8767
./gradlew run
```

LAN-режим использует открытый HTTP без TLS и без входа. Любое устройство, которое может подключиться к этому Wi-Fi-IP, получает одинаковые полные права: читает Chat/API, загружает и индексирует файлы, удаляет общие источники и отправляет запросы модели. Трафик не зашифрован; узел, способный перехватить Wi-Fi-трафик, может украсть session-cookie и получить доступ к истории и памяти этого workspace. Интерфейс показывает это предупреждение.

Используйте режим только в доверенной домашней Wi-Fi-сети. Не включайте гостевую/публичную сеть и не настраивайте перенаправление портов. Listener принимает только `192.168.2.160:8767`, не `0.0.0.0`; любое другое сетевое сочетание IP/порта отклоняется. Если закреплённый IP не принадлежит машине, запуск завершается ошибкой. Ollama остаётся на loopback и напрямую по сети недоступна.

Cookie сессии имеет флаги `HttpOnly` и `SameSite=Strict`, скользящий срок действия — 30 дней. Без TLS cookie не имеет `Secure` и передаётся открыто; это не является аутентификацией. Каждый профиль браузера получает отдельный Chat-workspace, но workspace не защищает от узлов, перехватывающих HTTP-трафик. Источники и индекс общие.

Chat-turn сохраняется сервером до запуска и проходит состояния `queued`, `running`, `completed`, `cancelled`, `failed` или `interrupted`. Интерфейс не ждёт генерацию в запросе отправки: он показывает очередь/выполнение и позволяет перейти к другой сессии. Кнопка «Отменить» отменяет ожидающий ход или прерывает активный запрос к provider; для DeepSeek прекращение уже принятой удалённой обработки и тарификации не гарантируется. После reload тот же turn восстанавливается без повторной отправки. После перезапуска приложения незавершённые turns помечаются `interrupted` и требуют ручного повтора.

Chat-turn проходят через одну durable-очередь: одновременно выполняется один ход, остальные сессии ждут. Все inference POST-запросы к локальной Ollama используют общий interruptible gate; метаданные доступных моделей не блокируют этот gate. Сериализация охватывает chat generation, embeddings, retrieval/reranking и benchmark. Локальная Chat generation передаёт `temperature=0.0`, `num_predict=384`, `num_ctx=4096` и `num_thread=8`; embeddings и reranking передают `num_thread=8`. Это параметры каждого запроса, не глобальная настройка `ollama serve`. Local RAG не подсчитывает полный prompt перед генерацией: границу context window и возможный context shift контролирует Ollama.

## Проверки

```bash
./gradlew test
xvfb-run -a -s '-screen 0 1440x1000x24' ./gradlew browserTest
```

Детерминированные тесты используют временную SQLite, синтетические документы, тестовый PDF-процесс и fake HTTP-сервисы Ollama/DeepSeek на loopback. Помимо RAG и benchmark проверяются no-login HTTP, точный LAN bind и отказ от Cloud-провайдера в LAN-каталоге, изоляция Chat-workspace между браузерами при общей коллекции, очередь параллельных сессий, отмена queued/running turns, восстановление состояния после reload/restart, сериализация Ollama inference и точное значение `num_thread=8` для Chat, embedding и reranking запросов. Обычные тесты не требуют секретов и не обращаются к внешним API.

`test` не включает browser journey. `browserTest` запускает настоящее приложение и Chromium под Xvfb; на Linux нужны `xvfb-run` и зависимости Chromium, которые Playwright сообщает при первом запуске. Browser acceptance проверяет основные RAG/Chat journeys и два отдельных browser contexts с приватной памятью и общей коллекцией.
